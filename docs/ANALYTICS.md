# Optional GA4 page views

Set `GA_MEASUREMENT_ID` in the deployment environment to the value in `.env.example`, then restart the Node process. Missing or blank values disable Analytics entirely. Invalid IDs stop startup through Zod validation. No ID is embedded in application code. Do not enable Analytics on test servers using a real property.

Before enabling it, open the GA4 property's **Admin → Data streams → web stream → Enhanced Measurement** and turn Enhanced Measurement **off**. Also ensure the Google tag has no extra destinations, automatic user-provided-data collection, event creation rules or other tags configured. These settings are managed by Google, not by this repository. `send_page_view: false` alone does not disable Enhanced Measurement. This integration cannot inspect or change your authenticated GA property settings.

The shared public-page head loads the local initializer first, then one asynchronous Google `gtag.js` script. The initializer queues one manual `page_view` for the static public page with `send_page_view: false` on configuration. An initialization guard prevents duplicate configuration and page views. Both configuration and event receive the same canonical page location, static site title and permitted referrer origin. The initializer never reads the current page query/fragment, document title, form values or downloader results. Query strings and fragments are excluded even on the home page. No click, download, form, search, scroll, history or downloader event handlers are installed. GA4 can still produce its standard automatically collected session/engagement events; “page views only” describes the application's explicit events, not a promise that GA4 has no internal events. The application does not emit `session_start`, change client/session identifiers or supply source, medium or campaign values.

The initializer reads the browser's available `document.referrer` once. The approval policy permits HTTP(S) origins with syntactically valid public-style DNS names, including non-default ports. It normalizes hostname casing and removes paths, query strings and fragments. It rejects credentials, encoded authorities, whitespace/control characters, backslashes, malformed or over-2048-character addresses, port zero, all IP literals, local/special-use hostnames, the canonical site's hostname and subdomains, the current hostname, and known TikTok/media-provider hostname families. Recognized sensitive query or fragment parameter names (tokens, authentication, passwords, secrets, signatures, credentials, sessions, job/analysis IDs and filenames) also exclude the entire referrer. Validation does not fetch the referrer or resolve DNS; it cannot prove that a public-style DNS name resolves to a public IP. The origin itself identifies a referring service and is not anonymous.

Permitted Google, Bing and other external origins are passed as `page_referrer` without `ignore_referrer: true`, allowing GA4's normal attribution rules to apply. Empty or excluded referrers are explicitly sent as an empty string on both configuration and event, preventing fallback to the raw address. No origin is invented. Browsers and referring sites may omit referrers; unavailable or stripped information cannot be recovered. Same-site navigation does not supply a new referral origin. Existing cookie behavior, CSP, `Referrer-Policy` and script `referrerpolicy` attributes are unchanged.

Advertising personalization and Google signals are disabled. Analytics cookies request 30-day expiry with cookie refresh disabled. Confirm the property's server-side retention and any required consent arrangements before activation; the project has no consent banner. The privacy policy discloses the optional provider, identifiers, technical network data, cookies and this limitation.

Only the public-page render routes receive the script tags and additional CSP sources. API, health, ready, preview, job, SSE, download, crawler and redirect routes retain their original CSP and contain no Analytics integration. Error responses contain no Analytics tags. Script sources add only `https://www.googletagmanager.com`; collection/image sources add that origin and `https://*.google-analytics.com` (including regional collection endpoints). No script `unsafe-inline`, `unsafe-eval`, Google Ads or broad Google domains are added.

Production verification after an authorized deployment:

1. In browser DevTools, enable Network preservation and filter for `gtag/js` and `g/collect`. With a fresh browser session, follow a genuine existing Google Search result to the site, without adding UTM parameters or overriding the referrer. Inspect `document.referrer` locally and confirm it is legitimately available. Do not paste sensitive URLs into shared logs.
2. Confirm one Google tag load and one initial `page_view` (`en`) per document. Inspect query and POST payloads: `dl` must be the canonical public page without query/fragment, `dt` the static page title, and `dr` only the permitted origin (or absent/empty when no permitted referrer exists). Other automatic engagement/session events are not duplicate page views. Verify the measurement ID matches the intended stream.
3. Visit directly and navigate between public pages. Check that no external origin is fabricated. Exercise the downloader with non-sensitive test data and confirm no submitted URLs, titles, identifiers or filenames enter collection payloads. API/download responses must not load the tag. Blocked tags must leave the UI functional.
4. Enable debug mode using Google Analytics Debugger in a test browser and open **Admin → Data display → DebugView** for the correct property. Confirm the initial `page_view` parameters and absence of duplicate application page views or manual session events. Disable the debugger afterwards. Confirm developer/internal traffic filters do not obscure the production check.
5. For attribution verification, use a separate normal, non-debug fresh session from a genuine Google result and inspect Realtime, then processed Traffic acquisition reports for **Session source / medium** and **Session default channel group**. No synthetic source/medium, UTM tags, fabricated referrers or automated search clicks are needed. Referrer availability alone does not guarantee a new session or its channel classification; property settings, existing sessions, consent, browser blocking, unwanted referrals and reporting delays also matter. Check those in the live property if new eligible sessions remain Direct. Historic sessions will not be repaired retroactively. Compare Search Console only over equivalent windows while accounting for clicks versus sessions.

Automated unit/integration tests cover allowed and rejected referrers, consistent configuration/event parameters, canonical metadata, duplicate initialization and private-route exclusion. Browser tests use local fixture referrers and a Google-tag transport stub to inspect intercepted collection-shaped payloads; no hits reach Google. These tests verify the application's parameters and CSP compatibility, not Google's SDK transport behavior or live GA4 classification. Those require the production checks above.

# Optional GA4 page views

Set `GA_MEASUREMENT_ID` in the deployment environment to the value in `.env.example`, then restart the Node process. Missing or blank values disable Analytics entirely. Invalid IDs stop startup through Zod validation. No ID is embedded in application code. Do not enable Analytics on test servers using a real property.

Before enabling it, open the GA4 property's **Admin → Data streams → web stream → Enhanced Measurement** and turn Enhanced Measurement **off**. Also ensure the Google tag has no extra destinations, automatic user-provided-data collection, event creation rules or other tags configured. These settings are managed by Google, not by this repository. `send_page_view: false` alone does not disable Enhanced Measurement. This integration cannot inspect or change your authenticated GA property settings.

The shared public-page head loads the local initializer first, then one asynchronous Google `gtag.js` script. The initializer queues one manual `page_view` for the static public page. It sets canonical page location and static site title on both configuration and event, with an empty referrer. It never reads the current URL, document title, form values or downloader results. Query strings and fragments are excluded even on the home page. No click, download, form, search, scroll, history or downloader event handlers are installed. GA4 can still produce its standard automatically collected session/engagement events; “page views only” describes the application's explicit events, not a promise that GA4 has no internal events.

Advertising personalization and Google signals are disabled. Analytics cookies request 30-day expiry with cookie refresh disabled. Confirm the property's server-side retention and any required consent arrangements before activation; the project has no consent banner. The privacy policy discloses the optional provider, identifiers, technical network data, cookies and this limitation.

Only the public-page render routes receive the script tags and additional CSP sources. API, health, ready, preview, job, SSE, download, crawler and redirect routes retain their original CSP and contain no Analytics integration. Error responses contain no Analytics tags. Script sources add only `https://www.googletagmanager.com`; collection/image sources add that origin and `https://*.google-analytics.com` (including regional collection endpoints). No script `unsafe-inline`, `unsafe-eval`, Google Ads or broad Google domains are added.

After deploying, use a clean browser to inspect the Google `g/collect` request and GA4 Realtime. Confirm one `page_view` per public page load, canonical `dl`, static `dt`, empty `dr`, and no form/download/search events. Try a page with a sensitive dummy query and interact with the downloader; none of that data should appear in Analytics. Blocked tags or absent configuration must leave the UI functional. Automated tests stub the Google script and do not send hits to a real property.

References: [Google page-view guidance](https://developers.google.com/analytics/devguides/collection/ga4/views), [configuration reference](https://developers.google.com/analytics/devguides/collection/ga4/reference/config), [Enhanced Measurement settings](https://support.google.com/analytics/answer/9216061), [Google CSP guidance](https://developers.google.com/tag-platform/security/guides/csp).

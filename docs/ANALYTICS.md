# Optional GA4 visits and download events

Set `GA_MEASUREMENT_ID` in the deployment environment to the value in `.env.example`, then restart the Node process. Missing or blank values disable Analytics entirely. Invalid IDs stop startup through Zod validation. No ID is embedded in application code. Do not enable Analytics on test servers using a real property.

Before enabling it, open the GA4 property's **Admin → Data streams → web stream → Enhanced Measurement** and turn Enhanced Measurement **off**. Also ensure the Google tag has no extra destinations, automatic user-provided-data collection, event creation rules or other tags configured. These settings are managed by Google, not by this repository. `send_page_view: false` alone does not disable Enhanced Measurement. This integration cannot inspect or change your authenticated GA property settings.

The shared public-page head loads a deferred local initializer. By default, the Google tag loads only after the visitor selects Allow analytics; Decline leaves the downloader usable without contacting Google. The footer reopens these preferences. The initializer queues one manual `page_view` for the static public page with `send_page_view: false` on configuration. An initialization guard prevents duplicate configuration and page views. Both configuration and event receive the same canonical page location, static site title and permitted referrer origin. The initializer never reads the current page query/fragment, document title, form values or downloader results. Query strings and fragments are excluded even on the home page. Fixed downloader events are emitted with only a media category: metadata_request, format_selected, download_attempt, download_prepared, download_requested, download_success, download_failure, download_cancelled. Unknown events and arbitrary event fields are rejected. download_success is emitted only after an authenticated status check confirms server delivery; preparation or clicking Save alone never counts as success. Server delivery does not prove that the file was saved on the device. No arbitrary click, form, search, scroll or history handlers are installed. GA4 can still produce its standard automatically collected session/engagement events; the fixed list describes the application's explicit events, not a promise that GA4 has no internal events. The application does not emit `session_start`, change client/session identifiers or supply source, medium or campaign values.

The initializer reads the browser's available `document.referrer` once. The approval policy permits HTTP(S) origins with syntactically valid public-style DNS names, including non-default ports. It normalizes hostname casing and removes paths, query strings and fragments. It rejects credentials, encoded authorities, whitespace/control characters, backslashes, malformed or over-2048-character addresses, port zero, all IP literals, local/special-use hostnames, the canonical site's hostname and subdomains, the current hostname, and known TikTok/media-provider hostname families. Recognized sensitive query or fragment parameter names (tokens, authentication, passwords, secrets, signatures, credentials, sessions, job/analysis IDs and filenames) also exclude the entire referrer. Validation does not fetch the referrer or resolve DNS; it cannot prove that a public-style DNS name resolves to a public IP. The origin itself identifies a referring service and is not anonymous.

Permitted Google, Bing and other external origins are passed as `page_referrer` without `ignore_referrer: true`, allowing GA4's normal attribution rules to apply. Empty or excluded referrers are explicitly sent as an empty string on both configuration and event, preventing fallback to the raw address. No origin is invented. Browsers and referring sites may omit referrers; unavailable or stripped information cannot be recovered. Same-site navigation does not supply a new referral origin. Existing cookie behavior, CSP, `Referrer-Policy` and script `referrerpolicy` attributes are unchanged.

Advertising personalization and Google signals are disabled. Analytics cookies request 30-day expiry with cookie refresh disabled. Confirm the property's server-side retention before activation. GA4_REQUIRE_CONSENT defaults to true; acceptance is stored locally and can be withdrawn in the footer. The privacy policy discloses the optional provider, identifiers, technical network data, events, cookies and local server counters.

Only the public-page render routes receive the script tags and additional CSP sources. API, health, ready, preview, job, SSE, download, crawler and redirect routes retain their original CSP and contain no Analytics integration. Error responses contain no Analytics tags. Script sources add only `https://www.googletagmanager.com`; collection/image sources add that origin and `https://*.google-analytics.com` (including regional collection endpoints). No script `unsafe-inline`, `unsafe-eval`, Google Ads or broad Google domains are added.

Production verification after an authorized deployment:

1. In browser DevTools, enable Network preservation and filter for `gtag/js` and `g/collect`. With a fresh browser session, follow a genuine existing Google Search result to the site, accept optional analytics, without adding UTM parameters or overriding the referrer. Inspect `document.referrer` locally and confirm it is legitimately available. Do not paste sensitive URLs into shared logs.
2. Confirm one Google tag load and one initial `page_view` (`en`) per document. Inspect query and POST payloads: `dl` must be the canonical public page without query/fragment, `dt` the static page title, and `dr` only the permitted origin (or absent/empty when no permitted referrer exists). Other automatic engagement/session events are not duplicate page views. Verify the measurement ID matches the intended stream.
3. Visit directly and navigate between public pages. Check that no external origin is fabricated. Exercise the downloader with non-sensitive test data and confirm no submitted URLs, titles, identifiers or filenames enter collection payloads. API/download responses must not load the tag. Blocked tags must leave the UI functional.
4. Enable debug mode using Google Analytics Debugger in a test browser and open **Admin → Data display → DebugView** for the correct property. Confirm the initial `page_view` parameters and absence of duplicate application page views or manual session events. Disable the debugger afterwards. Confirm developer/internal traffic filters do not obscure the production check.
5. For attribution verification, use a separate normal, non-debug fresh session from a genuine Google result and inspect Realtime, then processed Traffic acquisition reports for **Session source / medium** and **Session default channel group**. No synthetic source/medium, UTM tags, fabricated referrers or automated search clicks are needed. Referrer availability alone does not guarantee a new session or its channel classification; property settings, existing sessions, consent, browser blocking, unwanted referrals and reporting delays also matter. Check those in the live property if new eligible sessions remain Direct. Historic sessions will not be repaired retroactively. Compare Search Console only over equivalent windows while accounting for clicks versus sessions.

Automated unit/integration tests cover allowed and rejected referrers, consistent configuration/event parameters, canonical metadata, duplicate initialization and private-route exclusion. Browser tests use local fixture referrers and a Google-tag transport stub to inspect intercepted collection-shaped payloads; no hits reach Google. These tests verify the application's parameters and CSP compatibility, not Google's SDK transport behavior or live GA4 classification. Those require the production checks above.

References: [Google page-view guidance](https://developers.google.com/analytics/devguides/collection/ga4/views), [configuration reference](https://developers.google.com/analytics/devguides/collection/ga4/reference/config), [Enhanced Measurement settings](https://support.google.com/analytics/answer/9216061), [Google CSP guidance](https://developers.google.com/tag-platform/security/guides/csp).

## Private dashboard and CLI reporting

October 28 implementation update: the authenticated private dashboard is implemented but default-off until credentials are configured. See [ADMIN.md](ADMIN.md) for password/session setup and [the implementation report](BLOCKER_FIXES_2026-10-28.md) for local verification. It reuses the existing operational/GA4 read services, without adding a collector. CLI reporting remains available. No production deployment is implied.

You can use the private dashboard or open the existing GA4 property in Google Analytics. In Reports, use Events for download_success and Demographic details for Country. For a combined view, create a Free form Exploration with Country and Event name, Event count and Active users, filtered to download_success. Add a scoped custom dimension named Media type with event parameter media_type if you want MP4/MP3/image/ZIP breakdowns; custom dimension registration affects future data. GA4 geography comes from Google's collection processing, without adding a separate geolocation API or sending country labels from JavaScript. There is no country allowlist on collection; coverage still depends on consent, blockers, VPNs, Google processing and thresholds. Counts cannot identify every visitor or reconstruct past events.

Disable Enhanced Measurement as described above: automatic file_download events do not represent this application's completed job delivery. This repository does not log into or change your Google property. No live Google collection was sent during automated tests.

For independent server counts, set OPERATIONS_ENABLED=true and OPERATIONS_DATA_DIR to a private absolute VPS directory owned by the PM2 user (for example /var/lib/tiksavemp4/operations). Never use public/ or a web-served directory. The application generates a private operations.key and stores an SQLite database; back up the key and database together, excluding them from Git and release artifacts. Run npm run analytics:report -- 2026-10-01 2026-10-28 from the project as the same PM2 user, with its environment loaded. Dates are optional, defaulting to the last 30 UTC days; at most 730 days are accepted. It prints JSON, never exposes a reporting HTTP endpoint, and does not interrupt active jobs. Detailed jobs/errors/country breakdowns default to 30 days; daily totals persist for up to 730 days. The trackingStarted timestamp identifies when this deployment started recording, rather than suggesting historical counts.

Server countries default to XX (unknown). TRUST_COUNTRY_HEADER must stay false unless the loopback reverse proxy overwrites X-TikSave-Country from a validated geolocation source and the origin cannot be reached by visitors. Never forward an untrusted visitor-supplied header. GA4 country reports do not require this option. Local download totals are job counts, not unique people. Rejected/rate-limited requests are separate; rate-limit errors are sampled at most once per minute per route to bound storage.

Optional CLI Google reporting also requires GA4_PROPERTY_ID (numeric property ID, not the G- measurement ID), GA4_SERVICE_ACCOUNT_FILE pointing to a private service-account JSON file, the Analytics Data API enabled in that account's Google Cloud project, and Viewer access granted to its client_email on the property. Without these credentials, local counts remain available and Google reports explicitly say unavailable. The credential file is never served or logged. The existing measurement ID in .env.example is preserved.

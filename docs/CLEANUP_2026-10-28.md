## 1. Project cleanup summary

The cleanup was implemented in the existing dirty working tree. A before-inventory
and Git status were recorded before changes; unrelated earlier modifications were
preserved. Changes consolidate duplicate validators, separate test-only storage
from production code, remove repeated small allocations, replace unrelated .NET
ignore boilerplate with project-specific protections, remove an empty documentation
stub and provide a current documentation index.

This cleanup preserves behavior; it does not silently repair or declare resolved
the previously audited MP3 failure, client startup race or missing dashboard.

## 4. Refactoring summary

- `src/shared/download-contracts.ts` now owns the identical opaque-capability
  and progress schemas. API/frontend exports retain their original names and
  validation behavior; photo intents use the same capability validator.
- `apiErrorSchema` reuses the existing job error shape instead of declaring an
  identical object twice. Response envelopes and error paths remain unchanged.
- `InMemoryJobStore` now lives exclusively under `tests/fixtures`; production
  `src/services/memory-store.ts` contains only the existing service/claim types.
  Its sole value-import caller was the mock fixture. Store TTL, capacity,
  cancellation and subscriber behavior are unchanged and still tested.
- `blogCoverSrcset` resolves its fixed public directory once per module instead
  of once per card; filesystem existence checks and dynamic fixture behavior
  are preserved. No caching of request results or private data was added.
- XML escaping reuses a fixed entity table instead of allocating one inside
  every replacement callback. Escaping output and JSON-LD handling are unchanged.

No yt-dlp invocation, FFmpeg arguments, image decoding, ZIP processing, download
queue, rate limit, DNS pinning, redirect checks, capability lifetime, abort
handling, file streaming or cleanup boundary was rewritten.

## 5. Code quality and measured changes

The existing formatter/linter/type settings were used. New shared types and
fixtures follow strict TypeScript without `any`. Nine boundary regression cases
exercise valid source-reported progress, missing values, malicious/out-of-range
progress, opaque capabilities and unchanged error envelopes. Existing tests were
not removed or weakened.

The `.gitignore` is now focused on Node builds/dependencies, tests, private
configuration, credentials, databases, backups, logs and local editor output.
Irrelevant Visual Studio/.NET build patterns were removed after the inventory
confirmed this is a Node-only repository. Existing `.env.example`, publisher
examples, private configuration/data and screenshot protections remain; database
sidecars/private key protections are explicit. `git check-ignore` confirmed real
`.env`, operational keys and publisher-private files are ignored while the
environment example remains available. `.env.example` now documents the optional
existing operations secret without adding a value or rotating any key.

[Local measurements](cleanup/metrics.json):

- Compiled `memory-store.js`: 2,865 → 51 bytes; test implementation no longer
  emitted as runtime code.
- Browser downloader bundle: 487,885 → 487,400 bytes (485-byte reduction).
- Alternating six-round local XML microbenchmark, 100,000 escaping operations per
  round: median 237.78 → 201.12 ms, with identical output. This narrow measurement
  is not a page-speed, production throughput or Core Web Vitals claim.

   implementation and regression. Validators were consolidated without relaxing
   container/audio/duration/size verification.
2. Submitting before the dynamically loaded downloader handler is ready can
   navigate to JSON. The earlier controlled reproduction remains valid; a
   timing-dependent browser pass does not fix it. Address module readiness with
   an accessible safe fallback in a separate functional change.
3. The required private dashboard and secured authentication remain incomplete.
   No replacement dashboard was created as part of cleanup.
4. A release needs a reviewed artifact/revision including the local dirty/new
   files, correct asset cache invalidation and the production verification gates
   in the current runbook. The old baseline commit alone omits local work.
5. Actual VPS egress/proxy/Cloudflare/permissions/backup restoration, Linux
   performance/capacity, deployed SEO/consent changes and GA4 account settings
   remain operator-verification items. No production service was changed/tested
   destructively during cleanup.
6. Plan the unsupported ESLint tooling update separately. Historical generated
   screenshots and ambiguous assets remain on the review list; they were not
   removed to manufacture a file-count reduction.
